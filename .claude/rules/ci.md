# CI, the release and the devcontainer

CI runs every check on every pull request and on `main`; what a change here does is seen on its pull request, and architecture 3.1 holds the detail.

- **Checks.** `.github/workflows/ci.yml` calls the shared workflows of `.github` by the SHA of one release's tag, the same in every `uses:` (R58, R64, R68) — `secrets.yml`, `dco.yml`, `documents.yml`, the documents check, and `go.yml`, the four recipes of `.claude/rules/go.md` (R18) — and runs the jobs Binaries: `just release-files v0.0.0-ci` and `just binaries-samples <folder>` in the `toolchain` stage, which holds what `toolchain-core`, the release's stage, does — the step «The stage of the release» fails the job once it holds more, by the awk of «Toolchain stages» of `go.yml`, which «As in the pinned .github» holds it to (R62, R64) —, then `.github/binaries.sh <dist> <binary> <samples> <reference>` runs each of the six binaries on a runner of its own system and holds what it builds to what linux/amd64 built, byte for byte (R41). "Binaries / build" takes the image of `toolchain` and the caches of Go from the cache by the composite action `altnovatrail/.github/.github/actions/toolchain`, at the SHA of the shared workflows, with `check: binaries` — once before its work, and once at the end with `save: "true"`, which saves on a push to `main` alone —; Dependabot moves it with them, so a move of `.github` brings its steps, and a `docker run` of the job mounts the Go caches by the lines of the action's header; «As in the pinned .github» fails the job if the references to `.github` are not at one SHA or the mount is not those lines (R49 .github; R58, R61, R64). A change to a command of the CLI or to its samples changes `binaries.sh` with it. `codeql.yml` calls the shared `codeql.yml` with `languages: go`, which takes the Go archive by the `ARG`s of the `toolchain-core` stage, which `toolchain` is built from (R06, R62); `scorecard.yml` runs OpenSSF Scorecard.
- **The devcontainer.** `.devcontainer/` is byte for byte what spec's `tools/new-repo/` builds for the kind `go` at the submodule's tag, and a move to a tag takes it afresh, but for a change of the template's comments alone, which waits for the next change beyond comments (R51, R54, R68): `toolchain-core`, `toolchain` — the core with its `SHELL` alone, so the shared checks keep one image — and `devcontainer` (R62). A tool that only the tests need goes into `toolchain`, and a tool that a release or `ci-lint`, `ci-vuln` and `ci-licenses` run, into the core (R47 .github); gopls comes from its lock file, `.devcontainer/gopls/`. `devcontainer.yml` builds the `devcontainer` stage on amd64 and arm64 when `.devcontainer/**` changes, and `.github/devcontainer.sh <image> <dockerfile> <architecture>` checks each tool against its `ARG` (R44).
- **The release.** `release.yml` calls the shared `release.yml` of `.github` once CI is green on `main`: the next patch of `RELEASE_LINE`, and only when something in its `paths` changed — what a release is built from, listed in `release.yml` itself; a file the code comes to embed goes into that list (R18, R23, R52). `just release-files <version>` builds `dist/` from the commit's tree in the stage `toolchain-core` — six binaries, the licenses `release-licenses` names, `SHA256SUMS` — reproducibly, and the shared workflow signs each file (R07, R38; R77 spec). A new version of the format is a new release line (R52).
- **The rest.** `.github/dependabot.yml` says what Dependabot raises, and the references to `.github`, the action among them, in one pull request, the group `shared-workflows` (R58, R64); `.github/codecov.yml` holds `codecov/patch` to 90% (R48 spec); `.sonarcloud.properties` is SonarCloud's scope; `.bestpractices.json` holds the answers of project 16385 on bestpractices.dev, and a change that changes an answer changes the file (R48 spec). The tools the justfile pins, govulncheck and go-licenses, are raised by hand (R04).
